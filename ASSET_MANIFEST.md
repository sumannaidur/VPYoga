## GLB validation result
`models/yoga-character.glb` is a valid glTF 2.0 file but contains **one 24-vertex cube** ("YogaCharacterPedestal"): no skeleton, no character, **no animation clips**. The README that shipped with it (rigged character, 4 clips) is inaccurate. The site therefore uses **image-based** poses; Three.js is used only for procedural scenes (below), not for the character. The pose player is isolated in `src/surya.js` (`setStep`) so a real rigged model can replace it later.

## Needed from the client
Rigged GLB with 12 Surya clips; real, approved testimonials + photos; social links; privacy/terms pages; per-programme pages; a form backend; confirmation of bio, credentials and breath cues.

## WebGL scenes (src/gl/, lazy-loaded, paused off-screen, skipped for reduced motion / no WebGL)
| Scene | File | Notes |
|---|---|---|
| Hero, Surya, final CTA: sun rays + embers | `ambient.js` | rays/embers intensity scrubbed by scroll via `state.js` |
| Programme orbs on stone platforms | `orbs.js` | programme art under a glass lens; tracks the DOM `<li>` so GSAP reveals drive it; hover/focus lifts the orb |
| Meditation lotus, water, falling petals | `lotus.js` | fully procedural; `state.lotus.open` is scrubbed by scroll |
Each has an HTML/image fallback already in the page. Add `?` nothing; to compare, disable WebGL in the browser.

## Realistic photography (src/photos.json, src/photos.js)
Hero background, "A journey within" figure and the six programme orbs load licensed Pexels photos (`data-photo` slots) and fall back to the original artwork per slot if a photo cannot load. Photos were chosen from page metadata and **have not been visually reviewed**; swap any in `src/photos.json`. For production run `python3 scripts/fetch-photos.py` (needs internet + Pillow) to self-host optimised WebP and switch `local` to true. Credits render in the footer.
